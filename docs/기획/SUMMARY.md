## 📋 주요 결정 사항

### 1. Phase 1 컨셉: "거래처 고정 모드"

**의미**:
```
한 번에 한 거래처만 작업
→ 앱 시작 시 거래처 선택
→ 전체 화면이 해당 거래처로 고정
→ 다른 거래처 작업 시 명시적 전환 필요
```

**장점**:
- ✅ 개발 기간 단축 (2주 vs 4주)
- ✅ 사용자 혼란 방지
- ✅ 안정성 향상

**단점**:
- ❌ 거래처 전환 시 화면 리로드
- ❌ 여러 거래처 동시 비교 불가

**결론**: Phase 1 빠른 출시 → 피드백 수집 → Phase 2 탭 기능 추가

---

### 2. 최우선 화면 6개 (MVP)

```
P0 (최우선):
1. 거래처 선택 화면
2. 메인 작업 공간
3. 품목 선택 팝업 ★
4. 발주 화면
5. 판매 화면
6. 품목 관리

★ = 공통 컴포넌트 (재사용)
```

**이것만 있으면**:
- 발주 입력 가능
- 판매 입력 가능
- 재고 자동 반영
- 기본 업무 처리 가능

---

### 3. 3분할 레이아웃 표준화

**모든 입력 화면 동일 구조**:
```
┌─────────────┬───────────────┐
│ 좌: 전체    │ 우: 최근거래  │ (상단 60%)
├─────────────┴───────────────┤
│ 하: 3탭 (등록/임시/이력)     │ (하단 40%)
└─────────────────────────────┘
```

**장점**:
- 학습 곡선 감소
- 코드 재사용
- 일관된 UX

## 💡 혁신 포인트

### 1. 우측 "최근 거래 품목" 패널
```
전통적 방식:
검색 → 선택 → 수량 입력 → 추가
(4단계, 약 20초)

Tran 방식:
수량만 입력 → 완료
(1단계, 약 5초)

→ 75% 시간 절감!
```

### 2. 임시저장 기능
```
전통적 방식:
중단 시 데이터 유실 위험

Tran 방식:
언제든 [임시저장]
나중에 [불러오기]

→ 데이터 유실 0%
→ 업무 유연성 향상
```

### 3. 자동 연계 처리
```
발주 확정 → 자동:
- 구매 레코드 생성
- 입고 예정 수량 반영

판매 확정 → 자동:
- 재고 즉시 차감
- 채권 자동 생성

견적 확정 → 자동:
- 단가 정책 저장
- 품목 리스트 등록

→ 수작업 최소화
```

## 🎨 UI/UX 설계 원칙

### 1. 일관성 (Consistency)
- 모든 입력 화면: 동일한 3분할 레이아웃
- 품목 선택: 항상 동일한 팝업
- 버튼 위치: 항상 동일한 곳

### 2. 효율성 (Efficiency)
- 최소 클릭 수
- 최근 거래 품목 우선 표시
- 키보드 단축키 지원 (계획)

### 3. 명확성 (Clarity)
- 현재 거래처 항상 표시
- 상태 색상 코드
  - 정상: 파란색
  - 주의: 주황색
  - 위험: 빨간색

### 4. 오류 방지 (Error Prevention)
- 재고 부족 시 판매 불가
- 필수 입력 표시 (*)
- 거래처 전환 시 미저장 확인
