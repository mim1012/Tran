# 자동화 경계 정의서 (MVP)

> **원칙**: 자동 생성, 수동 확정
> **범위**: 발주 / 구매 / 판매 / 재고 (기존 와이어프레임 내)
> **작성일**: 2026-02-10

---

## 1. 핵심 원칙

```
기계가 하는 것: 확정된 데이터 복사, 숫자 계산, Draft 생성, 알림
사람이 하는 것: 금액 결정, 수량 확인, 확정 버튼, 외부 전송
```

모든 자동 생성은 Draft 상태로만 만든다. 확정은 반드시 사람이 한다.

---

## 2. MVP 자동화 4개 플로우

### 2.1 발주 완료 → 구매 자동 생성

```
발주서 작성 ─── 👤 수동
발주서 전송 ─── 👤 수동
발주 완료 ──── 👤 수동
    │
    ▼ 자동
    ├→ 🤖 Purchase 레코드 생성 (State = PendingDelivery)
    ├→ 🤖 Inventory.PendingInQuantity += 수량
    └→ 🤖 CompanyProduct.OrderCount++
```

경리가 안 해도 되는 것: 구매 대장에 같은 내용 다시 입력

---

### 2.2 입고 확정 → 재고 자동 반영

```
물품 도착 ──── 실물 이벤트
입고 수량 확인 ─── 👤 수동 (실물 검수)
불량 수량 기입 ─── 👤 수동
입고 확정 ──── 👤 수동
    │
    ▼ 자동
    ├→ 🤖 Inventory.ConfirmedQuantity += 입고수량
    ├→ 🤖 Inventory.PendingInQuantity -= 입고수량
    └→ 🤖 InventoryTransaction 이력 기록 (Type=Inbound)
```

경리가 안 해도 되는 것: 재고 대장에 입고 수량 수동 기입

---

### 2.3 판매 확정 → 재고 자동 차감

```
판매 등록 ──── 👤 수동 (품목/수량/단가)
재고 부족 경고 ─── 🤖 자동 (알림만, 차단 아님)
판매 확정 ──── 👤 수동
    │
    ▼ 자동
    ├→ 🤖 Inventory.ConfirmedQuantity -= 출고수량
    ├→ 🤖 Inventory.PendingOutQuantity -= 출고수량
    └→ 🤖 InventoryTransaction 이력 기록 (Type=Outbound)
```

경리가 안 해도 되는 것: 재고 대장에 출고 수량 수동 차감

---

### 2.4 견적 확정 → 단가 자동 적용

```
견적서 작성 ─── 👤 수동 (단가 결정)
견적서 발송 ─── 👤 수동
거래처 확정 ─── 👤 수동
    │
    ▼ 자동
    ├→ 🤖 CompanyPrice 업데이트 (거래처별 단가)
    ├→ 🤖 PriceHistory 이력 저장
    └→ 🤖 CompanyProduct 자동 등록 (자주 거래 품목)
```

경리가 안 해도 되는 것: 단가표 수동 갱신, 품목 리스트 수동 등록

---

## 3. 자동/수동 한 장 요약

```
👤 수동 (사람이 버튼 누르는 것)
────────────────────────────
  발주서 작성/전송/완료
  입고 수량 확인 (실물 검수)
  판매 등록/확정
  견적서 작성/발송

🤖 자동 (확정 후 시스템이 하는 것)
────────────────────────────
  발주 → 구매 레코드 복사
  입고 → 재고 수량 증가
  판매 → 재고 수량 차감
  견적 → 단가/품목 반영
  모든 변동 → 이력 기록
```

## 4. 이벤트 → 핸들러 매핑

| 이벤트 | 발생 시점 | 핸들러 |
|--------|----------|--------|
| `OrderCompleted` | 발주 완료 | PurchaseCreationHandler, PendingInboundHandler |
| `PurchaseDelivered` | 입고 확정 | InventoryInboundHandler |
| `SaleConfirmed` | 판매 확정 | InventoryOutboundHandler |
| `QuotationConfirmed` | 견적 확정 | PricePolicyHandler, CompanyProductHandler |

모든 핸들러는 트랜잭션 내 실행. 실패 시 롤백.

## 5. 화면별 자동화 연결

기존 와이어프레임 기준으로 어디에서 자동화가 작동하는지:

### 발주 화면 (`04-발주-화면.md`)

```
[발주서 보내기] 클릭
    → OrderState = Completed
    → 🤖 구매 관리 화면에 Purchase 자동 생성
    → 🤖 재고 화면에 입고예정 수량 반영
```

### 구매 관리 화면 (`PurchaseWindow.xaml`)

```
[입고 확정] 클릭
    → PurchaseState = Delivered
    → 🤖 재고 화면에 확정재고 자동 증가
    → 🤖 입고예정 수량 자동 차감
```

### 판매 화면 (`05-판매-화면.md`)

```
[판매 등록] 클릭
    → SaleState = Confirmed
    → 🤖 재고 화면에 확정재고 자동 차감
```

### 재고 화면 (`InventoryWindow.xaml`)

```
직접 조작 없음 - 읽기 전용 (자동 반영 결과 조회)
예외: [재고 조정] 버튼 → 수동 재고 수정 (실사 후)
```

### 견적서 화면 (`QuotationWindow.xaml`)

```
[견적 확정] 시
    → 🤖 발주/판매 화면의 단가 자동 적용
    → 🤖 품목 선택 팝업의 "자주 거래 품목"에 자동 등록
```

## 6. 구현 순서

```
① 판매 확정 → 재고 출고 (매일 쓰는 기능, 최우선)
② 발주 완료 → 구매 생성 (발주-구매 연결)
③ 입고 확정 → 재고 입고 (구매-재고 연결)
④ 견적 확정 → 단가/품목 반영 (견적-단가 연결)
```

이 4개가 되면 경리가 같은 데이터를 여러 번 입력하는 일이 없어진다.
